# 查事实 + 写稿

追热点 Agent 的第 4 步。读前几步的 `热点/今天日期/pick.json`（角度、数据来源）和 `brief.json`（开头、结构、节奏、结尾），产出：

- `facts.json`：所有用到的事实和数，每条有出处
- `calc/`：要算的数的脚本和结果
- `script.json` / `script.md`：一屏一屏的稿子，下一步（出画面）直接读

格式见 `references/script-format.md`，写法见 `references/writing.md`。**动笔前两份都读一遍。**

用户没跑前几步、直接说「帮我写个 xx 的稿」：先问清楚角度（想讲什么、给谁看），没有 `brief.json` 就按 `writing.md` 的写法和「每 10 秒至少换 3 屏」来。

## 步骤

1. **读档案**：`热点/profile.md` 里的「写稿偏好」「手上已有的数据」「能做的画面」。偏好和 brief 冲突时**听偏好**（例：brief 建议「先给上一期对账」，偏好写了「不对账」，就不对账）。
   - 档案里没写「配音」：问用户一句「配旁白，还是纯字幕 + 音乐？」，答案记进档案。用户没意见就默认纯字幕 + 音乐（`voice: none`）。配旁白（`voice: tts`）由出画面那一步用 MiniMax 念，要 `MINIMAX_API_KEY`（没有也能在网页上生成，见 `hot-render`）。
   - 有 `热点/ip/ip.md`（账号的 IP）：读它，旁白和字幕照里面的口气、用第一人称写；口头禅一条片子最多一次；「不说」里的词一个都不许出现。人设只管**怎么说**：数和事实照样只来自 `facts.json`，不编没发生的经历。细节见 `../hot-agent/references/ip.md`。

2. **列要用的事实**：照 `brief.json` 的结构，把每一段要用到的事实和数列出来（比分、时间、名单、历史记录、要算的概率……）。

3. **查事实**，每条写进 `facts.json`：
   - 赛果、时间、名单这类**事件事实**：要官方（主办方、官方账号）或权威媒体，两个来源对不上听官方。官方页面打不开、几家媒体又对不上的：只写大家都对得上的部分（比如只写日期不写钟点），对不上的部分不进稿子，在回复里列出来。
   - 评论区原话（放进 `quote` 卡的）也是一条 fact，`level` 写「评论原话」，`source` 写哪条视频。
   - 用 `pick.json` 的 `data_sources` 和你的联网搜索找；用户手上有的数据（档案里写的）直接用，`level` 写「用户自有数据」。
   - 查不到的：**不写进稿子**。这一段要是缺了它就讲不通，换一个讲法，或者在回复里告诉用户缺什么。
   - 你没有联网能力：只用用户给的数据和 `pick.json` 里写明的来源，在回复里说明哪些没核实。

4. **算数**（角度要算的时候）：
   - 在 `热点/今天日期/calc/` 写 Python 脚本算，跑出来的结果写进 `facts.json`（`level: 计算`，`source.calc` 写脚本路径）。脚本要能重跑。
   - 用户已经有现成的模型产出（档案里写了），直接读它的结果，不要自己重写一个模型。
   - 模型能简单就简单。一个模型的假设（「按今年胜率模拟 10 万次」）写成一条 fact，方法细节放简介，**不进旁白**。
   - 结果太离谱（某队 99%、概率加起来不是 100%）先查脚本，别直接写进稿子。

5. **写稿**，照 `brief.json` 和 `writing.md`：
   - 第一屏照 brief 的 `hook`：热点事件 + 最扎眼的数。纯字幕（`voice: none`）时，brief 的第一句压成 14 字以内的 `caption`，背景放进 `kicker`；`script.md` 的表去掉「旁白」那一列。
   - 段落按 brief 的 `sections`，每段由观众心里的问题带出来。
   - 节奏：每 10 秒换屏次数不少于 brief 的 `pace_cuts_per_10s`（没有就 3）。一屏只放一件事。
   - 结尾照 brief 的 `stance`：落在一件事实上，或者最后一屏用 `vote` 放站队按钮。
   - 写成 `script.json`（格式见 `script-format.md`），同时写 `script.md` 给人看：表格「# / 秒 / 画面 / 大字 / 旁白 / 出处」，表下面写标题和标签。
   - 标题按平台字数：抖音 ≤ 30、小红书 ≤ 20、B 站 ≤ 80，不加空格；前半句放能被搜到的词（热点里的人名、队名、事件名），用 `brief.json` 的 `title_ideas` 起步，每个平台 2–3 条。

6. **检查**（在用户的工作文件夹里运行）：

   ```bash
   python3 <这个skill的文件夹>/scripts/check_script.py
   ```

   - 「错误」全部改掉，再跑，直到没有错误。不许为了过检查删掉有用的数，要么给它补上出处，要么换讲法。
   - 「提醒」逐条看，有道理就改。
   - 脚本查不出来的，你自己再对一遍 `writing.md`「不要这样写」那张表（排比、对仗、金句、说明书式列举、解释方法），把改了哪几句记在 `script.md` 最后「自检」一节。

7. **回给用户**：`script.md` 的表、推荐的抖音标题、总时长。数是算出来的就说一句「数来自 xx 模型 / 脚本」。缺的事实、没核实的地方单独列。问一句要不要接着出画面（下一步 skill：`hot-render`）。

## 别做

- 别编数、别凑「大约」：稿子里每个数都要在 `facts.json` 里，检查脚本会抓。
- 别在旁白里解释模型、报接口、报花费。
- 别把对手的原话、原句搬进稿子；`quote` 卡只放评论区观众原话或官方说法，并写明是谁说的。
