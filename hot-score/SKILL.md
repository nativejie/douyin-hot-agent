# 值不值得做

追热点 Agent 的第 2 步。读第 1 步（`hot-topics`）的 `热点/今天日期/shortlist.json`，给每个热点打分，挑出今天主推的一个，产出 `pick.json` 给下一步（拆同题爆款）。

用户没跑第 1 步、直接点名一个热点问「能不能蹭」：自己建一个只有这一个热点的 `shortlist.json`（字段照第 1 步的格式，`angle` 先问用户想怎么做，用户没想法就你提一个），再往下走。

## 准备

- 环境变量 `TIKHUB_API_KEY`（第 1 步设过就不用管）。这一步每个热点搜两次，每次 0.01 美元，7 个热点约 0.14 美元。
- 读 `热点/profile.md`。里面要有一行「抖音昵称：xxx」，没有就问用户一句加上（用来认出搜到的是不是自己的视频，自己的不算竞争）。用户不想填也行：第 3 步看到标题、内容很像用户以前做过的（对照 profile 里写的作品），标成「疑似自己的」，不算竞争，并在回复里问一句是不是。

## 步骤

1. **给每个热点写一个角度搜索词**：在 `shortlist.json` 每个 item 里加 `"kw"`，是别人如果做了同一个角度、标题里大概会有的两三个词。例：
   - 角度「让 AI 重算 S16 四强夺冠概率」→ `"kw": "S16 夺冠概率"`
   - 角度「AI 拉北京历年初雪日期」→ `"kw": "北京初雪 历年"`
   - 别把整句角度塞进去，搜不到东西。

2. **跑同题搜索**（在用户的工作文件夹里运行）：

   ```bash
   python3 <这个skill的文件夹>/scripts/competition.py --me "抖音昵称"
   ```

   报「接口没返回」时设 `TIKHUB_NOPROXY=1` 再跑。别连着重试，失败的请求也扣钱；某一个热点失败了，就在打分里写「没查到」，不要为它单独重跑整批。

3. **读 `competition.md`**，每个热点看两组：
   - **同题**（热点原词，近 1 天）：今天谁在做。全是官方号、新闻号、50 万粉以上的大号在发快讯，说明「报新闻」这条路被占了，但有角度的内容可能还空着。
   - **同角度**（`kw`，近 7 天）：有没有人做过我们这个角度。**逐条判断搜到的是不是真的同一个角度**（搜「金鸡奖 获奖概率」出来的明星采访、搜「王者荣耀 夺冠概率」出来的英雄胜率，都不算）。只有算数的那几条参与打分；一条都不算 = 空着。在 `score.md` 里写明哪几条算、哪几条不算。
   - 评赞比 ≥ 0.1 = 评论区在吵（有立场之争），对蹭热点是好事。
   - 标了【自己的】或你判断「疑似自己的」：不算竞争，但说明这个题用户做过，写进理由。
   - 某组搜索报错 = **不知道**，不是「很差」：对应几项给 0 分，结论最高到「备选」，回复里说清楚要先自己去抖音看一眼。
   - 搜到的视频不到 3 条 = 样本太少，「有人看」「有得吵」都最高给 8 分（两三条新闻号的评赞比说明不了什么）。

4. **核实数据拿不拿得到**：角度要用到的数据（赛事战绩、历年记录、官方成绩、名单），用你的联网搜索找一下来源。
   - 找到了：记下来源（网站名 + 链接），写进 `data_sources`，并标来源等级：**官方**（主办方、官方机构、官方账号）/ **权威媒体** / **转载或品牌自述**（车企宣传稿、微博转发）。品牌自述的数据能用，但稿子里要说「据 xx 官方」。
   - 网页工具读不出内容的下载页（比如数据集要点按钮才下载）：用户工作区里已经有这份数据就算找到；没有就按「要拼」算。
   - 找不到核心数据、或者只能拿到一部分（比如只有平均值、只有几年），或者要付费、要登录：「今天能做完」给 0 分。
   - 你没有联网能力：写「数据未核实」，这项给一半分，并在回复里提醒用户。
   - **查清这个数是什么时候的**：热点里说的「首次突破」「最新」，可能是几个月前年鉴里的旧数被翻出来。是旧数就在 `risk` 里写明，「还在热」照算，但角度要能接住（「去年底就破了」也能做），接不住就「今天能做完」给 15。
   - **别凭记忆写数据**。

5. **打分**（满分 100，每项写一句理由，理由里引用 `competition.md` 或 `shortlist.json` 的数）：

   | 项 | 分 | 怎么给 |
   |---|---|---|
   | 还在热 | 20 | 上榜 < 12 小时 20；12–24 小时 15；24–48 小时 8；更久 3。涨跌为负再扣 5；热度排在 `hot.md` 全部条目的后一半再扣 5。上榜时间 = shortlist 里的 `age_h` + 从 `hot.json` 的 `fetched_at` 到现在过去的小时数。只在 B 站热搜上的（没有上榜时间）：B 站热搜前 10 名 15，11–30 名 10，更后 5；「后一半」只和 B 站那一节比 |
   | 角度还空着 | 25 | 只看判断为「真同角度」的那几条：没有或最高赞 < 1000 给 25；1000–1 万 15；> 1 万 5 |
   | 有人看 | 15 | 同题最高赞 ≥ 1 万、或中位赞 ≥ 1000、或有小号爆款给 15；中位 100–1000 给 8；更少给 3。不到 3 条最高 8；搜索报错给 0 |
   | 有得吵 | 15 | 同题评赞比 ≥ 0.1 给 15；0.05–0.1 给 8；更低给 3；不到 3 条最高 8；搜索报错给 0 |
   | 今天能做完 | 25 | 核心数据有一个官方 / 权威来源、今天就能拿到（或档案「手上已有的数据」里就有）给 25；要从几处拼、或只有品牌自述 / 新闻报道给 15；核心数据拿不到给 0。档案里有现成数据、能接着上一条做的，在理由里写明，分数接近时优先它 |

   结论：≥ 70「做」；50–69「备选」；< 50「不做」。再按下面几条改：
   - 「今天能做完」是 0 → 一律「不做」（不能当备选）。
   - 有搜索报错 → 最高「备选」。
   - 碰到 profile 里写的「不碰」→ 一律「不做」。
   - **有风险的题照分数给结论，不降级**，在 `risk_flag` 里写明是哪一类，交给用户决定（追热点 Agent 会停下来问）：
     - 政府政策：国务院、部委、地方政府发布的政策、规定、调控措施（统计局、央行公布的**数据**本身不算，评价政策才算）。
     - 未成年人当主角；饭圈争议；接近「预测」「竞猜」的赛事题（标题标签要换成「概率」「模拟」）。
     - 档案里已经写明做过、或者明说可以做的题型（例：档案写了「S16 世界赛 AI 模拟各队夺冠概率」），算用户已经同意过，`risk_flag` 留空，`risk` 里照写注意事项。

   **结论是「做」的里面分数最高的是主推**；分数接近（差 5 分以内）时选上榜时间更短的。没有「做」的，就推「备选」里最高的，并说明卡在哪。

6. **存到 `热点/今天日期/`**（再打一次就覆盖）：
   - `score.md`：给人看的表（热点 / 总分 / 五项分 / 结论 / 一句话理由），表下面写主推的完整理由和数据来源。
   - `pick.json`：给下一步读：

     ```json
     {"date": "2026-11-07", "word": "热榜原词", "angle": "角度", "kw": "角度搜索词",
      "score": 85, "scores": {"热": 15, "空": 25, "看": 15, "吵": 15, "做完": 15},
      "data_sources": [{"name": "来源名", "url": "链接", "what": "拿什么数据"}],
      "competitors": {"same_angle": ["真同角度里赞最高的最多 3 条链接"], "same_topic": ["同题里赞最高的 2 条链接"]},
      "risk": "风险和注意事项", "risk_flag": "政府政策 / 未成年人 / 饭圈 / 近似预测，没有填 null", "backup": "备选的热点原词（只能是「做」或「备选」，不能是「今天能做完」为 0 的），没有填 null"}
     ```

7. **回给用户**：打分表，主推哪一个、为什么（两三句，带数），备选是哪个。再问一句要不要接着拆同题爆款（下一步 skill：`hot-breakdown`）。全都「不做」就直说今天没有好题，建议过几个小时重新抓（第 1 步加 `--force`），别硬推。

## 别做

- 别编搜索结果里没有的数（赞、评论、粉丝）。
- 别因为分数低就偷偷改角度再打一遍；想换角度，先跟用户说。
- 别在回复里报接口地址、密钥、花了多少钱。
