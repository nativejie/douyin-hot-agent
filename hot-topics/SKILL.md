# 抓热点

追热点 Agent 的第 1 步：把抖音今天的热榜拉下来，去掉不能碰的，挑出这个账号今天能蹭的几个。下一步（判断值不值得做）读这里产出的 `shortlist.json`。

## 准备（第一次用）

1. **TikHub 密钥**：去 tikhub.io 注册，在用户后台生成 API Key，设成环境变量 `TIKHUB_API_KEY`（Mac / Linux 写进 `~/.zshrc`：`export TIKHUB_API_KEY=...`；Windows 用「系统环境变量」）。**不要把密钥写进任何文件、也不要贴进对话**。抓一次约 0.004 美元；充值不退，先充最低的 5 美元。
2. **账号档案**：看当前文件夹有没有 `热点/profile.md`。没有就问用户这三句，原话记进去：
   - 你的账号做什么内容？（例：AI 工具、职场、美食、游戏解说）
   - 你能做哪种画面？（数据卡片 / 清单盘点 / 实测录屏 / 口播 / 都行）
   - 有什么题你不碰？
   以后每次直接读，不再问。

## 步骤

1. 运行抓取脚本（在用户的工作文件夹里运行，产出会放进 `热点/今天日期/`）：

   ```bash
   python3 <这个skill的文件夹>/scripts/fetch_hot.py
   ```

   同一天 1 小时内抓过，脚本会直接复用，不再花钱；用户明确要「最新的」才加 `--force`。
   报「接口没返回」时，多半是代理掐断了响应：设环境变量 `TIKHUB_NOPROXY=1` 再跑一次。别连着重试，失败的请求也扣钱。

2. 读 `热点/今天日期/hot.md`。脚本已经按规则滤掉了时政、军事、灾难、伤亡、案件、国际冲突。**你再人工过一遍**，下面这些也去掉：
   - 涉及具体普通人的遭遇（求助、纠纷、维权、隐私、未成年人）
   - 逝者、疾病、悲剧，哪怕标题写得很温和
   - 宗教、民族、地域对立
   - 明星的私生活传闻（恋情、绝交、离婚爆料）；作品、舞台、颁奖可以
   - 人物的伤病、健康原因退出；正常退役、转会、夺冠可以
   - 带外交色彩的（外国元首、外籍人员参与的国家项目、国际关系）
   - 政府政策：可以留，但角度只能「照政策算一笔账」（几点睡、多花多少钱），不评价政策对不对，不拿具体的人（尤其未成年人）举例；风险里写明
   - 纯站内玩法（翻唱挑战、舞蹈挑战、滤镜特效），除非账号就是做这个的

3. **先合并同一件事**：同一件事常常用好几个词条上榜（例：「T1战胜KC晋级4强」「S16淘汰赛热点赛事观察」「BLG晋级四强后发文」）。合成一个热点，`word` 用热度最高的那条，`hot` 取最高，`age_h` 取最小，`trend` 取有值的那条（几条都有取最大，都没有写 null，**别写 0**），其余词条写进 `related`。

4. 按 `profile.md` 挑 **5–8 个**；够格的不到 5 个就少给，别凑数。挑的标准，按重要性：
   - **这个账号能拿出别人没有的角度**：能算数据、能做实测、能盘点清单、能用 AI 做出点什么。光是复述新闻的不挑。档案里写了账号是做 AI 的，角度里就必须有 AI 在干活（AI 算、AI 实测、AI 做出东西），不能只是普通的数据卡片。
   - **还在热**，看这几样（hot.md 开头有每列的意思）：
     - 上榜时间：< 24 小时优先；24–48 小时只在涨跌为正、或角度特别好时挑；> 48 小时一般不挑（飙升榜上的老词是旧事翻红，可以看）。
     - 涨跌：只有上升榜 / 飙升榜的条目有。为空表示没数据，不扣分，按上榜时间和热度判断；为负说明在掉。
     - 在几个榜上：只算「上升榜」「飙升榜」这两个额外的信号。娱乐类条目几乎都同时在热搜榜和娱乐榜上，这是榜单结构，不算更热。
   - **今天能做完**：要拍实物、要采访、要等结果出来的不挑。数据拿不拿得到这一步**不用去查**，在风险里写「xx 数据待核实」，下一步 `hot-score` 会核实。
   - **有话可吵更好**：大家立场不一样（支持谁、值不值、对不对），评论区会吵起来。
   - 标了 ⚠️ 的（标题含预测、竞猜）可以挑，但标题和标签里换成「概率」「模拟」。

5. 每个热点写清楚：
   - **角度**：一句话，具体到这条视频讲什么。「用数据算一算 xx」，不是「蹭一下 xx」。
   - **为什么现在**：引 hot.md 里的数（热度、涨跌、上榜几小时、在几个榜上）。
   - **风险**：可能踩什么线，没有就写「无」。

6. 存两份到 `热点/今天日期/`（同一天再挑一次就直接覆盖）：
   - `shortlist.md`：给人看的表（热点 / 角度 / 为什么现在 / 风险）。
   - `shortlist.json`：给下一步读，格式：

     ```json
     {"date": "2026-11-07", "profile": "账号方向一句话",
      "items": [{"word": "热榜原词", "related": ["同一件事的其他词条"], "angle": "角度", "why_now": "热度 1093 万，上榜 1.4 小时，还在涨", "risk": "无", "hot": 10930000, "age_h": 1.4, "trend": 12}]}
     ```

     `hot` 填原始整数；`why_now` 里写成「万」、取整；没有的数填 `null`，不要省略字段。

7. 回给用户：shortlist 的表，加一句你最推荐哪一个、为什么。再问一句要不要接着判断值不值得做（下一步 skill：`hot-score`）。

## 别做

- 别编热度、排名、上榜时间：数字只能来自 `hot.md`。
- 别替用户把被滤掉的热点捞回来。用户自己点名要做，先说清楚为什么被滤，再让用户决定。
- 别在回复里报接口地址、密钥、花了多少钱。
